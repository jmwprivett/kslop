### What has NOT been tried — Quest 2

1. **A data-only kcall via a writable, legitimately-called kernel function pointer.** This is the biggest gap. You have proven kernel data writes and proven writable shared-cache data pages; nobody has surveyed 23A341 kernel `__DATA` for a dispatch/vtable/ops slot that (a) is called with attacker-influenced arguments and (b) whose pointer is stored in *writable* memory where a KRW write of an already-signed value (or a packed/relative form) could land. Modern arm64e signs heap pointers, but plenty of legacy dispatch arrays, `IOExternalMethod` tables, and `sysctl` handlers are exactly the candidates REA was brought in to census — and the census hasn't run.
2. **The arm64e signing-gadget hunt itself** (kernel function that signs an attacker pointer with the kernel IA key — Fugu15/jb3 class). Proposed in `rea-exploit-research.md`; no evidence it ran on the physical kernelcache. Without it, "PAC-correct kernel call primitive" has no candidate source.
3. **`pmap_sign_user_ptr` under a *kernel* JOP/key context.** VM code swaps in `kernkeylo/hi_el1` around the SPTM call — that machinery is for *user* JOP keys; the kernel-context variant (if the GENTER service permits it) was never tested. If it works, `ip_kobject` destination PAC stops being dead.
4. **Task-for-pid / host-privileged-port minting routes for a genuine task right** (Rank 3). Rejected in analysis as insufficient *for code signing*, but never tested as a *kcall* carrier — a kernel-minted task right plus `thread_convert` gets you a signed PC for a thread you can resume, i.e. a one-argument "call any function with a thread-shaped context". Nobody has connected those two documented facts.
5. **A kernel-thread hijack kcall** (find a quiet kernel-owned thread via KRW, `thread_set_state` it remotely through whatever right the exception path yields, resume). All the pieces are individually documented; the combination is untried.
6. **The `PT_ATTACHEXC` Rank-0 probe itself.** It is deliberately first in your own escalation ladder and it costs no primitive. It hasn't been run.
7. **KRW lease/broker for multi-host use** (interprocess file lock or lease FD). Designed in the springboard doc; not implemented. It blocks the port *and* the SpringBoard-resident goal, and it is pure engineering, no exploit required.
